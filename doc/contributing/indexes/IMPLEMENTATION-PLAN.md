# Every index a type has, inherited from its bounding box: the implementation plan

[Back to the index](00-INDEX.md)

The indexes of every type are generated from the box type it inherits them from. This plan holds
the tasks that bring every index there and the rule the multi-entry classes follow. It continues
the row G102 of the generation plan of MobilityDB #3928, whose record is kept whole at the end.

## Part III — the rule of a multi-entry class

**THE RULE (the owner, 2026-11-23).** A multi-entry class serves an operator if and only if,
whenever the operator holds on the whole value, some piece of the value passes the leaf test
against the query; the recheck removes the false positives. Which operators pass is what the
operator reads, a fact stated once beside the operator in the manifest the generator reads.

| What the operator reads | Leaf test on a piece | Operators |
|---|---|---|
| the value (elements, components, instants) | the span or box test that holds on some piece when the operator holds: `&&` for `&&`, `<@` for `<@`, `&&` for `@>`, `<@` for `=` | `&&`, `@>`, `<@`, `=` of sets and span sets; `?&&`, `%&&` of temporal values |
| a face of the box, which a piece reaches | the operator itself, with the recheck forced (MEOS answers `recheck = false` for it on a box of the whole value) | the position operators (`<<`, `&<`, `>>`, `&>` and their time and space forms); `-|-` of span sets, whose bounding span has its ends in the first and last components (`adjacent_spanset_spanset`) |
| the same box (`~=`, its one meaning since `cd0648eab3`) | `<@`, every piece lying within the query | `~=` of temporal values |
| the distance to the box | the distance to the piece's box, a lower bound, rechecked | `\|=\|` |
| the interior of the box, or a face no piece need meet | answered by the marked key of the whole box | `&&`, `@>`, `-|-` of temporal boxes |

**THE WHOLE-BOX KEY (the owner, 2026-11-23, "B then").** A multi-entry class of a temporal box
carries, beside the pieces, one key of the whole box, marked as a structure of its own through
`bbox_same_structure`, as `MEOS_FLAG_PARTS` keeps the boxes of each structure in a subtree of their
own in GiST and SP-GiST: the box operators read the whole-box keys alone and are as selective as a
single-entry class, and the value predicates read the piece keys alone and skip every subtree of
whole-box keys. The hull key of mest #32, unmarked among the pieces, fetches 2000 of 2000 values
for both on the 2000 trips whose boxes meet a query that 61 paths cross. A multi-entry class of a
temporal box therefore serves every operator of its single-entry class, at one key per value more.
The span sets need no whole-box key: their `&&` and `@>` read the components.

**THE POINT CLOUDS.** The 9 classes of `tpcbox`, `tpcpoint` and `tpcpatch` (`439_tpc_gist.in.sql`,
`440_tpc_spgist.in.sql`) hold the 25 strategies of a spatiotemporal box, and classify as `stbox`;
a piece of a `tpcpatch` is the box of a run of its patches and carries their pcid.

**THE PORT.** The method is the one of `contrib/mobilitydb` of mest (`consistent_mest.c`,
`spanset_mest.c`, `temporal_mest.c`, `tnumber_mest.c`, `tpoint_mest.c`) for 4 families; the
generator carries it to every family, the whole-box key marked rather than mixed with the pieces.

## Acceptance of the whole

- Every type is indexed through the box `type_bboxtype` states, by classes generated from that box
  type, and no index class of MobilityDB is written by hand.
- Every multi-entry class serves every operator of its single-entry class, each operator by the
  leaf test its tier states, and answers as the scan on every generated test.
- `contrib/mobilitydb` of mest is retired, and the user document states the indexes of every type.
