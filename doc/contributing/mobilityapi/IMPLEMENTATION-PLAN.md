# MobilityAPI beyond its declared classes — Implementation plan

Decided by the owner, 2026-11-21 ("go with your recommendations"). MobilityAPI
master at the start: `11eb22f`.

| row | what | state |
|---|---|---|
| U1 | The description of a raster collection completed under `/req/edr/rc-collection-info`: `parameter_names` (one Parameter per band, as `asCoverageJSON` names them), `output_formats`, `keywords`, a `type` on every link, a `data` link per EDR query. No class declared. | MERGED as MobilityAPI #96 (`baf7261`): `/collections` and `/collections/{cid}` write one description; on master `/collections` listed a raster collection with a null `extent`, which `/req/collections/src-md-success` C forbids; the user document states it at v1.1.0, MERGED as MobilityDB #3904 |
| U2 | Moving Features collections answer the EDR queries `area`, `radius`, `cube` and `trajectory`, each the moving features the geometry meets, written in GeoJSON or MF-JSON and computed by MobilityDB; every collection then satisfies `collections`, and `collections` and `queries` are declared. | MERGED as MobilityAPI #101 (`4858865`): a collection of geographies is related on the spheroid; `radius` is answered over moving points alone (`tgeompoint`, `tgeogpoint`); the functions MobilityDB composes over tnpoint, tpcpatch, tpcpoint, tpose and tquadbin, read from the catalog's compositions, are MERGED as MobilityAPI #102 (`d41015d`), and `th3index` and `ts2cell` alone link no query; the user document is MERGED as MobilityDB #3949 (v1.5.0), and v1.6.0, stating the compositions, is MERGED as MobilityDB #3952; a bbox over a collection of geographies, on `/items` and the EDR `cube`, is the longitude and latitude region `eOverlaps` decides against a geodetic box, a box crossing the antimeridian read as the two boxes either side of it, MERGED as MobilityAPI #103 (`2970dd1`), its specification v1.7.0 MERGED as MobilityDB #3953 |
| U3 | A raster collection answers `radius` (the coverage clipped to the buffer of a point, `within` and `within-units`, `distanceunits` stated), `cube` (`bbox` and `z`, `z` read and not applied as a raster has no vertical axis) and `instances` (each period of the collection an instance). | MERGED as MobilityAPI #97 (`d546339`): its radius and cube read the pixels `ST_Clip` reads on MobilityDB master `bc564ad1d4`, which carries U3a; the user document states it at v1.2.0, MERGED as MobilityDB #3909 |
| U3a | MobilityDB: `clip(raster, geometry)` places the clipped raster at the upper-left corner of the input, so a region right of the first column answers the wrong pixels, all null: on a 4 x 2 raster at (0, 2), `clip` to `ST_MakeEnvelope(2, 0, 4, 2, 4326)` answers upper-left x 0 and no value, where `ST_Clip` answers upper-left x 2 and the band's value. A MobilityDB pull request, merged before U3. | MERGED as MobilityDB #3905 (master `bc564ad1d4`): the subject's corner aligns the mask's grid, as PostGIS `RASTER_clip` passes it |
| U4 | CoverageJSON written in the spelling the client asks for, `application/prs.coverage+json` or, by default, `application/vnd.cov+json`; `covjson` declared. | MERGED as MobilityAPI #98 (`f7de535`): on MobilityAPI `d546339` `/coverage` answers 406 to `Accept: application/prs.coverage+json`; the user document states it at v1.3.0, MERGED as MobilityDB #3910 |
| U5 | OGC filings drafted for the owner, one per place where EDR 1.1 contradicts its own schemas, the service following the schema: `crs` as objects (`/req/edr/rc-crs`) or strings (`collection.yaml`); `f` (`/req/edr/rc-collection-info` J) or `output_formats` (`collection.yaml`); `observedProperty.id` required (`/req/edr/rc-parameters` F) or optional (`observedPropertyCollection.yaml`); one instance answered by the schema of the instance list (`/req/instances/src-md-success` B, `instances.yaml`); and an instance holding the `extent` of its collection (`/req/instances/src-md-success` C). | drafted in `ogc-filings/edr-*.md` for four of them, `f` being fixed on EDR's master; filed together once every implementing row of this plan is merged (the owner, 2026-11-21: "filing only when the full implementation is ready") |
| U6 | A MobilityAPI extension, marked as one: OGC holds no draft of a Stream part (the owner, 2026-11-21, from OGC), so the operations follow the Table 7 of the proposal MobilityAPI's continuous queries read, and no OGC class is claimed for them. A continuous query over a temporal geometry (`.../tgsequence/queries`) applies its window aggregations: MovingPoint `COUNT`, `LENGTH`, `INTERSECT`, `TO_TRAJ`; MovingLineString `COUNT`, `LENGTH`, `AREA`, `INTERSECT`; MovingPolygon `COUNT`, `AREA`, `INTERSECT`, each computed by MobilityDB. `VOLUME` is refused naming the function MEOS lacks. | MERGED as MobilityAPI #104 (`53fd81d`), ruled 2026-11-27: `COUNT` for every type; a moving point's `LENGTH` (distance travelled, geodesic in longitude and latitude), `TO_TRAJ` and `INTERSECT`; the `LENGTH` and `AREA` of what lines or polygons cover, `traversed_area` with its union, each overlap counted once, and `INTERSECT` with a WKT region; `LENGTH` and `AREA` in longitude and latitude refused, MEOS uniting on the plane alone; `VOLUME` refused. The value reaches the engine as WKB, which states no SRID, so the engine sets the collection's. The specification v1.8.0 is MERGED as MobilityDB #3957 |
| U7 | A MobilityAPI extension, as U6. Results of a continuous query delivered over a WebSocket channel beside Server-Sent Events, then to a Kafka topic named by the query's `channel`. | MERGED in two PRs: the WebSocket channel `GET .../queries/{queryId}/ws` as MobilityAPI #105 (`c810eb1`), one JSON message per result, a normal closure when the query stops; the Kafka topic a query names as MobilityAPI #106 (`aa15717`), one record per result keyed by the query's id, brokers from `MFAPI_KAFKA_BROKERS`, through franz-go v1.19.5, the latest release building with Go 1.25. The specification v1.9.0 is MERGED as MobilityDB #3961 |
| U8 | Coverages in NetCDF, written by `asGDALRaster` through GDAL's netCDF driver. LAS and LAZ stay out: they encode point clouds, not the coverage of a raster collection. | MobilityDB's writer of a format whose library writes only to a file is MERGED as MobilityDB #3913; the MobilityAPI side (`application/x-netcdf`, class `netcdf` of the Coverages draft) is MERGED as MobilityAPI #100. A format whose GDAL driver is absent is refused by MobilityDB's writer, "GDAL has no driver of the format"; the GDAL MEOS-API builds for the CI of the MEOS consumers carries the netCDF driver, MERGED as MEOS-API #286 |
| U8a | MobilityAPI's generator reads as raster types only the structs whose text reader answers a SQL type, so the `summarystats` record `BandStats` is no raster type. | MERGED as MobilityAPI #99 |
| U8b | MobilityDB: `asGDALRaster(r, 'VRT')` ends the server process, inside `GDALClose` of the VRT reading the source `raster_as_gdal` has closed; PostGIS's `ST_AsGDALRaster` does the same. The copy is closed before its source and VRT, which writes no pixel, is refused. | MERGED as MobilityDB #3921; the specification states the netCDF encoding at v1.4.0, MERGED as MobilityDB #3922 |
| U9 | The newer Part 4 draft (a Continuous Query resource with `id`, `pubtime`, `target`, `filter`, `queryResult`). | dropped: OGC holds no draft of a Stream part; the work there has not begun (the owner, 2026-11-21) |
| U11 | A proposal OGC can begin drafting the Stream chapter of Moving Features from (the owner, 2026-11-21: "propose a document with our working implementation that can be used to begin drafting the chapter"): the continuous query resource, its windows, its aggregations over temporal properties and temporal geometries, its lifecycle and its channels, each stated as a requirement with its abstract test, and with how MobilityAPI answers it and the test of its suite that measures it. Written once U6 and U7 are merged and green, from MobilityAPI master; the owner submits it. | drafted in `STREAM-PROPOSAL.md` from MobilityAPI master `bec7d9d`: twelve requirements, 1 to 5 keeping the numbering of the YY-999 document, each with its abstract test, how MobilityAPI answers it and the test that measures it, and the points left to the drafting group; the HTTP cycle of a property query and the Server-Sent Events over HTTP are stated as measured by no test of their own. The owner submits it |
