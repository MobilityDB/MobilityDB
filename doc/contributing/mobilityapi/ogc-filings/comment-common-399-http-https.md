Evidence from an implementation that meets this today, across three standards.

**The defect, measured.** The published OGC API – Common – Part 2 (20-024) writes its class identifiers only under `https://`, and cites Part 1's core as `https://www.opengis.net/spec/ogcapi-common-1/1.0/conf/core`, a string Part 1 never writes; its own OpenAPI document (`rConformance.yaml`) writes the same classes under `http://`. The OGC API – Coverages draft (19-087, 1.0.0rc4) writes all 132 of its identifiers under `https://`, while its OpenAPI document writes them under `http://` and OGC's executable suite `ets-ogcapi-coverages10` checks `http://www.opengis.net/spec/ogcapi-coverages-1/1.0/conf/core` by string equality (`ConformanceClass.byConformanceClass`). A server declaring only the draft's spelling fails that suite's conformance test. Moving Features Part 1 (22-003r3) inherits Part 2's class as `http://`.

**A candidate resolution.** One identifier per class, written alike in the conformance clause, the abstract tests, the OpenAPI document and the executable suite. If OGC moves to `https://`, a stated transition in which a server declares both spellings and a client accepts either, so that neither existing clients nor existing suites break.

**How MobilityAPI solves it.** [MobilityAPI](https://github.com/MobilityDB/MobilityAPI), an OGC API – Moving Features server over MobilityDB, names each class as its standard publishes it, and a class published under `https://` also under `http://`. `conformsTo` is a list, so a client comparing strings finds the class under either spelling, and the Coverages suite finds the identifier it checks. Classes published under `http://` alone (Common Part 1, Moving Features Part 1, EDR 1.1) are declared under that one.

**Evidence.** `conformsTo` in [`main.go`](https://github.com/MobilityDB/MobilityAPI/blob/459a02d/main.go) and `TestConformanceNamesEachClassAsPublished` in [`ats_routes_test.go`](https://github.com/MobilityDB/MobilityAPI/blob/459a02d/ats_routes_test.go), merged in MobilityDB/MobilityAPI#89; its conformance declaration: [`samples/conformance-declaration.json`](https://github.com/MobilityDB/MobilityAPI/blob/459a02d/samples/conformance-declaration.json). The measurements per standard are on https://github.com/MobilityDB/MobilityDB/wiki/Implementing-OGC-API-Common-in-MobilityDB and https://github.com/MobilityDB/MobilityDB/wiki/Implementing-OGC-API-Coverages-in-MobilityDB
