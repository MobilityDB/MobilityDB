Detailed Description

Error handling of the MEOS library.

A message reaches its reader through two channels, which differ in what the caller has to do next.

  • The error handler receives every message when it is raised, with its level, its code and its text: meos_error() calls the handler installed by meos_initialize_error_handler(), which prints it, logs it or hands it to the host. The levels are those of errorLevel.
  • The error number, read by meos_errno(), records that an error happened: the function that raised it returned its sentinel, and every frame above it passed that failure up, freeing what it had built. It keeps the code of the last error raised until meos_errno_reset() clears it.

Only a message of level MEOS_ERROR reaches the second channel. A warning, a notice or an information accompanies an answer, as liblwgeom's notices and the defaults the MF-JSON reader takes do, so it goes to the handler and leaves the error number as it is. This is how PostgreSQL reports them: an error ends the statement, while a warning is sent to the client and the log and the statement goes on. In the extension, meos_error() hands every message to ereport() at its own level.

liblwgeom reports through the same two channels, its errors and its notices being routed to meos_error() by the two handlers meos_initialize() installs (meos/src/temporal/meos.c). MEOS calls no GEOS function, so it installs no GEOS handler: the GEOS names the vendored raster core calls are answered in meos/src/geo/geo_geos_none.c, which ignores the handlers given to initGEOS() and routes an error to liblwgeom's.

A host that wants both channels installs its own handler, records the code of an error with meos_errno_set() and logs the other levels:

static void
host_handler(int errlevel, int errcode, const char *errmsg)
{
if (errlevel == MEOS_ERROR)
{
meos_errno_set(errcode);
host_remember_error(errmsg);
}
else
host_log_warning(errcode, errmsg);
}
