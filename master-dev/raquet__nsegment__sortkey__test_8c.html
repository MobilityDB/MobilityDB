Detailed Description

A program that tests that the sort keys of network segments and of Raquet tiles order and equate them as their comparison and their equality do.

A sort key is the string of bytes whose unsigned byte order is the order of a comparison and whose byte equality is the equality of the type, so that an engine that sorts, groups or joins values by their bytes answers as MobilityDB does. Over a corpus of network segments (four routes, the positions 0, 0.25, 0.5 and 1 in either order of the two ends) and of Raquet tiles (four tiles, two pixel types, three widths and two heights, pixels of small and large bytes, the same pixels with and without a nodata value, which raquet_cmp does not read), the program checks:

  • over every pair, that the comparison answers 0 exactly when the equality holds, and that swapping the operands swaps the sign;
  • over every triple, that the comparison is transitive;
  • over every pair, that the byte order of the keys is the comparison and that the keys are identical exactly when the equality holds. It also counts the pairs whose stored bytes order otherwise than the comparison, which is what an engine comparing the stored bytes answers.

The routes of the network segments come from the ways file the environment variable MEOS_WAYS_CSV names, by default ../examples/data/ways1000.csv, the one of the source tree read from meos/test, where the tests run, as spatialset_distance_test.c reads it. A corpus that is empty, as one of network segments is when no ways file holds their routes, is a failure, so that the checks are never made over nothing.

The program can be built as follows

gcc -Wall -g -I/usr/local/include -o raquet_nsegment_sortkey_test raquet_nsegment_sortkey_test.c -L/usr/local/lib -lmeos -lm
