Detailed Description

A program that tests that the comparison of circular buffers and of network points is a total order consistent with their equality, and that their sort keys order the sets and the temporal values of these types as their comparison does.

A sort key is the string of bytes whose unsigned byte order is the order of a comparison and whose byte equality is the equality of the type. An engine that sorts, groups or joins values by their bytes answers as MobilityDB does only when such a key exists, and a key exists only when the comparison is a total order that holds two values equal exactly when the equality of the type does. The program therefore checks, over a corpus of circular buffers (three SRIDs, coordinates that are negative, zero of both signs, large, infinite or NaN, radii that are zero of both signs, close neighbours, infinite or NaN) and of network points (several routes, positions zero of both signs, interior and one, and NaN):

  • which of the special inputs the input functions accept;
  • over every pair, that the comparison answers 0 exactly when the equality holds, and that swapping the operands swaps the sign;
  • over every triple, that the comparison is transitive;
  • over every pair of sets of one and of two values, and of temporal values of one and of two instants, that the byte order of the keys is the order of set_cmp and temporal_cmp, over the pairs these comparisons accept, since they refuse two values of different SRIDs.

The routes of the network points come from the ways file the environment variable MEOS_WAYS_CSV names, by default meos/examples/data/ways1000.csv of the source tree, read from the directory the program runs in.
